# Этап 15: авторизация

**Работает против живого проекта.** Вход, обмен приглашения, создание
профиля и удаление аккаунта пройдены целиком на `cinevault-dev`. Обе Edge
Functions выложены, `npm run check:functions` даёт 13 из 13.

Незакрытым остаётся одно: своё письмо. Пока нет домена и SMTP-отправителя,
подтверждение почты держится на встроенной рассылке Supabase с её жёстким
лимитом — для сотни человек этого не хватит.

## Что уже проверено

Прямо в браузере, на локальном сервере, без Supabase:

- экран входа и регистрации отрисовывается, все шесть полей регистрации на
  месте, переключение режимов работает;
- пустая отправка регистрации показывает **все** ошибки сразу, а не первую;
- 19 проверок из `authRules` проходят: кириллица в имени пользователя
  отклоняется, код приглашения переживает пробелы и дефисы, пароли сверяются,
  ошибки Supabase переводятся на русский;
- обе темы дают читаемые цвета, на ширине 375 пикселей горизонтального
  скролла нет.

Снимок экрана сделать не удалось: панель браузера в этой сессии не
отображается. Проверка шла по структуре страницы и вычисленным стилям.

Не проверено ничего, что требует сервера: настоящий вход, письма, обмен
приглашения на профиль, удаление аккаунта.

## Как посмотреть самому

```bash
npm start
```

Затем откройте `http://localhost:8765/?auth=preview`. Параметр включает
предпросмотр экрана входа поверх ещё локального приложения: формы можно
отправлять, проверки полей срабатывают, до сети дело не доходит.

Без параметра приложение открывается по-старому, из IndexedDB. **Так и
задумано на время перехода:** шлюз включается только при настроенном сервере,
иначе разработка остального встала бы до этапа 16. После переноса библиотеки
условие уйдёт — без аккаунта показывать будет нечего.

## Что нужно сделать, чтобы этап закрыть

1. Завершить [этап 14](STAGE_14.md) — без проекта Supabase дальше некуда.
2. Вписать адрес проекта и анонимный ключ в `src/config.js`
   (`SUPABASE_URL`, `SUPABASE_ANON_KEY`). Ключ публичный, это нормально.
3. Собрать клиент Supabase в один файл — сборщика в проекте нет:

```bash
npm install && npm run vendor:supabase
```

   Полученный `vendor/supabase.esm.js` коммитится в репозиторий, см.
   [vendor/README.md](../vendor/README.md).

4. Выложить Edge Function удаления аккаунта:

```bash
npx supabase functions deploy delete-account
```

5. Настроить письма: свой домен и SMTP-отправитель (Resend), русские шаблоны
   подтверждения почты и восстановления пароля. Пока домена нет, dev-проект
   работает на встроенной почте Supabase — этого хватает, чтобы пройти сценарий
   самому, но не для сотни людей.

## Как устроен вход

Регистрация закрытая, и это не проверка в форме, а устройство базы: аккаунт
без строки в `profiles` не видит ни одной записи. Профиль выдаёт только
`redeem_invite` в обмен на действующий код.

Отсюда порядок, который может показаться странным: **код приглашения
обменивается на профиль после первого входа, а не в момент регистрации.** До
подтверждения почты сессии не существует, а `redeem_invite` требует
`auth.uid()`. Поэтому код, имя пользователя и отображаемое имя запоминаются на
устройстве и применяются, как только сессия появилась. Если человек
подтверждает почту на другом устройстве, приложение спросит код ещё раз —
экран «Ещё один шаг».

Побочное следствие: зарегистрироваться без кода технически можно, но такой
аккаунт пуст и бесполезен — он ничего не видит и ничего не может. Полностью
закрыть регистрацию до проверки кода можно позже, хуком Supabase Auth.

## Открытый вопрос

Переносить ли локальную библиотеку в аккаунт автоматически при первом входе,
или спрашивать явно. Мой ответ — спрашивать: молча забирать данные в облако
неправильно, и это же даёт человеку выбрать, какой аккаунт считать своим.
Решается в этапе 16.
