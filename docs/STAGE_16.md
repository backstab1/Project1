# Этап 16: библиотека на сервере

Библиотека переехала в аккаунт. Локального хранилища записей в приложении
больше нет, файловых выгрузок и загрузок — тоже: источник правды один, и он на
сервере.

Решение убрать файлы принято заказчиком **27 августа 2026 года** и заменило
прежний план этапа, где библиотека переносилась в аккаунт из локальной базы
или из JSON-копии. Переноса нет: библиотека наполняется в аккаунте с нуля.

## Что теперь как работает

| Слой | Было | Стало |
| --- | --- | --- |
| хранилище записей | IndexedDB в браузере | Postgres, строки помечены владельцем, доступ по RLS |
| запись | транзакция IndexedDB | RPC `apply_library_changes` — одна функция, одна транзакция |
| настройки | store `settings` | `user_settings.data`, значения по умолчанию подставляет клиент |
| резервные копии | JSON вручную и копии на диск лаунчером | копии базы на стороне сервиса |
| импорт | JSON, CSV, TSV, XLSX, старый `localStorage` | ничего из этого не осталось |
| IndexedDB | основное хранилище | один снимок последней загрузки на аккаунт, только на чтение |

## Точка переключения

`main.js` обращается к библиотеке через `data/libraryStore.js` — это
единственное место, которое знает, откуда она берётся. Внутри — серверный
`libraryGateway.js` и снимок в IndexedDB. Интерфейс остался прежним: тридцать
два вызова в `main.js` не менялись, `src/domain/*` не менялся вовсе.

## Снимок вместо локальной базы

Снимок лежит в отдельном хранилище `snapshots`, по записи на аккаунт. Он нужен
для двух вещей:

- библиотека появляется сразу, а не после ответа сервера;
- при обрыве связи на экране остаётся последняя известная библиотека, а
  наверху — полоса «нет связи»; изменения в этом состоянии не принимаются.

При выходе из аккаунта снимок стирается: за чужим компьютером библиотека не
должна оставаться лежать в браузере после выхода.

Хранилища прежней локальной версии приложение больше не создаёт, но и не
удаляет: у того, кто открывал старую сборку, они остаются в браузере со своими
данными. Стирать их приложение не вправе.

## Оптимистичная блокировка: ревизия, а не `updated_at`

План этапа предполагал сравнение `updated_at` каждой строки. От этого пришлось
отказаться, и вот почему:

1. Приложение пишет пакетами, собранными из снимка всей библиотеки: перенос
   фильма между списками переписывает позиции соседей, удаление списка трогает
   все его фильмы. Построчная проверка не защищает пакет, который опирается на
   состояние соседних строк.
2. Удалённая на другом устройстве строка не оставляет времени, с которым можно
   сравнить: её просто нет.

Поэтому блокировка стоит на библиотеке целиком. `user_settings.revision` —
счётчик: каждый успешный пакет увеличивает его на единицу. Клиент запоминает
ревизию при загрузке и присылает обратно вместе с пакетом; если на сервере она
другая, пакет отвергается целиком, а приложение показывает «Библиотека
изменилась» и предлагает обновить её.

Код отказа — `PT409`, а не `40001`, как было задумано сначала. Класс 40 значит
«транзакция откачена, повторите», и PostgREST повторял такой запрос сам:
расхождение ревизий постоянное, поэтому повторы шли по кругу и ответ не
приходил вовсе. Коды вида `PTxxx` PostgREST превращает в HTTP-статус, так что
клиент получает честный 409 Conflict с тем же текстом. Поймала это ровно та
проверка, ради которой всё писалось.

Строка `user_settings` заодно служит замком (`select … for update`): два пакета
одного владельца не переплетаются.

## Что проверено

- `npm test` — 108 проверок доменной логики и перекладки полей;
- `npm run test:python` — 5 проверок лаунчера;
- в браузере: фасад хранилища, обновление схемы IndexedDB до снимка, витрина и
  вход без ошибок в консоли.

Против живого проекта — `npm run check:library`. Скрипт заводит двух временных
пользователей и проверяет:

- библиотека наполняется одним пакетом, ревизия поднимается с нуля;
- запись возвращается из базы такой же: карточка целиком, оценка зрителя,
  вложенность списков, квоты, порядок фильмов во франшизе, настройка;
- пакет применяется целиком: переименование, удаление и настройка вместе,
  удаление фильма забирает его связь с франшизой;
- пакет с устаревшей ревизией отвергается и ничего не записывает;
- сбойный пакет откатывается целиком, ревизия не двигается;
- чужая библиотека не видна и не удаляется посторонним.
