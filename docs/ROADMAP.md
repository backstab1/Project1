# Roadmap CineVault

Документ отвечает на два вопроса: где продукт находится сегодня и что делается
дальше. Подробности перехода на сервер — в
[SERVER_MULTIUSER_PLAN.md](SERVER_MULTIUSER_PLAN.md), история изменений —
в [CHANGELOG.md](../CHANGELOG.md).

## Где мы сейчас — 27 августа 2026

Версия `0.11.0-beta.1`. Библиотека переехала в аккаунт: локального хранилища
записей в приложении больше нет, как нет и файловых выгрузок и загрузок —
резервных копий JSON, выгрузки CSV, импорта таблиц и переноса старой базы.
Источник правды один, и он на сервере. Решение принято заказчиком 27 августа
2026 года; подробности — в [STAGE_16.md](STAGE_16.md).

`npm test` даёт 108 проверок из 108, `npm run test:python` — 5 из 5,
`npm run check:library` на `cinevault-dev` — 20 из 20. Миграция накатана,
этап 16 закрыт 27 августа 2026 года.

Что осталось незакрытым помимо этого:

- сервис негде открыть: хостинг и домен — остаток этапа 17. TMDB туда уже
  переехал: Edge Function `tmdb`, `npm run check:tmdb` — 11 из 11;
- друг не может открыть чужую библиотеку — переключатель видимости в разделе
  «Друзья» ждёт этапа 19;
- совместное колесо нельзя собрать из интерфейса, хотя серверное ядро сессии
  готово и проверено (включая общий момент старта вращения), — этап 20;
- визуальная проверка `qa/` приостановлена: она наполняла IndexedDB, которой
  больше нет. Ей нужен демо-аккаунт — см. [qa/README.md](../qa/README.md).

Вне плана за 25–27 августа закрыта **визуальная система 3.0**: нейтральная
палитра, типографическая шкала из семи ступеней, плотность (восемь плиток в
ряд при 1366×768 вместо пяти), плитка-постер, шапка с кабинетом, окна вместо
шторок, новое колесо и заставка загрузки. Направление и таблица изменений —
в [CINEVAULT_VISUAL_DIRECTION.md](CINEVAULT_VISUAL_DIRECTION.md), раздел 0.

## Куда идём

Цель — онлайн-сервис для аудитории до ста человек: библиотека принадлежит
аккаунту и доступна с любого устройства, друзья видят библиотеки друг друга,
колесо крутится совместно в реальном времени. Требование работы без интернета
снято после этапа 13 и не возвращается; `.exe` и переносимая сборка теряют
смысл вместе с ним. Файлы как способ хранить и переносить библиотеку тоже
остались в прошлом: их место заняли аккаунт и резервные копии базы.

Первоначальная цель — переносимое локальное Windows-приложение для библиотеки
до 500 фильмов — достигнута этапами 0–13 и остаётся основой: `src/domain/*`
переход не переписывает, чистые правила исполняются и в браузере, и в Edge
Functions.

## Что делаем дальше

Порядок именно такой: сначала то, что снимает промежуточное состояние, потом
то, что добавляет ценность.

### 1. Приёмка библиотеки живым аккаунтом

Автоматика прошла целиком; осталось пройти сценарий руками: добавить фильм,
собрать список, провести сессию колеса, войти со второго устройства и увидеть
то же самое.

### 2. Этап 17. Инфраструктура и доставка

Сделано: TMDB переехал в Edge Function с общим токеном и дневной квотой на
аккаунт, постеры отдаются с CDN TMDB по `poster_path`, локальный кэш картинок
и прокси в лаунчере убраны, сборки под Windows удалены.

Резервные копии сделаны своими силами, без платного тарифа: `npm run backup`
снимает копию через служебный ключ, `npm run restore` возвращает её, а
`npm run check:backup` проходит весь путь целиком — снять, потерять, вернуть
(9 из 9). Сборка статики — `npm run build:site`, каталог `dist/`.

Осталось и требует ваших действий:

- домен (порядка 10 $ в год) и проект на Cloudflare Pages;
- `APP_ORIGIN` в секретах функций — после появления адреса, для CORS;
- расписание для `npm run backup` на вашей машине;
- `CineVault.cmd` становится ярлыком на адрес сервиса;
- возвращение визуальной проверки `qa/` на демо-аккаунт.

### 3. Хвосты этапов 15 и 18

Обе задачи небольшие, и обе требуют не кода, а действия:

- своя почта: домен и SMTP-отправитель с SPF, DKIM и DMARC. Пока писем нет,
  подтверждение почты и восстановление пароля нельзя считать рабочими;
- приёмка друзей на двух живых аккаунтах, включая проверку приватности
  **прямым запросом к API**, а не через интерфейс. См. [STAGE_18.md](STAGE_18.md).

### 4. Этап 19. Чужая библиотека и общие оценки

Первая функция, ради которой пользователь заводит друга. Сюда же переезжает
долг из этапа 18: экран массового сопоставления старых оценок по именам с
аккаунтами.

### 5. Этап 20. Совместное колесо — довести

Ядро сделано досрочно и живёт на сервере: журнал `roll_events`, старт сессии,
серверный спин и сейвы проверены полной сессией до победителя, Edge Function
исполняет тот же `rollEngine.js`, что и браузер (`npm run check:functions` —
13 из 13). Осталась клиентская половина: подписка на Realtime, приглашение в
сессию, интерфейс совместной комнаты и присоединение посреди сессии.

### 6. Этап 21. Общие списки и коллекции

Единственное место, где два человека пишут в одну запись, и самая дорогая
часть перехода. Если сроки поджимают, режется первой: колесо и чужие
библиотеки дают ценность и без неё.

### 7. Волны 7–9

Расширенные метаданные TMDB и умные подборки — после перехода. Импорт из
Кинопоиска и IMDb в этот список больше не входит: файловых и внешних импортов
в приложении не будет.

## Блокеры и открытые вопросы

- **домен и почтовый отправитель** — блокируют закрытие этапа 15 и весь
  сценарий восстановления пароля;
- **судьба `.exe` и `launch.py`** — удалить или оставить ярлык на веб-версию;
  решение нужно к этапу 17;
- закрыто: **офлайн-сценарий** — библиотека живёт в аккаунте, без сети видно
  только снимок последней загрузки, и он не принимает изменения;
- **язык писем и ошибок Supabase** — по умолчанию английские, под русский
  интерфейс нужны свои шаблоны;
- закрыто: **как попадают в сервис** — регистрация закрытая, по кодам
  приглашений из восьми символов;
- открыто: **гостевой режим без регистрации** — в плане его нет.
